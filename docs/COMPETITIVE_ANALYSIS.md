# ChronoStack — Competitive Analysis

Descriptions are based on each project's public documentation (links given). No head-to-head benchmarks were run. Second pass: libfaketime, Stripe Test Clocks, Node MockTimers, Toxiproxy and Chaos Mesh pages were opened and checked ([SOURCE_VERIFICATION.md](SOURCE_VERIFICATION.md) §5, §7); the remaining rows are still knowledge-based. ChronoStack is **not** unique in its core mechanism — LD_PRELOAD time faking has existed for over a decade. Its potential differentiation is orchestration, safety, and lifecycle workflow.

| Tool | Problem solved | Architecture | Limitations | Audience | What ChronoStack can add |
|---|---|---|---|---|---|
| **libfaketime** — https://github.com/wolfcw/libfaketime | Fake system time for a process | `LD_PRELOAD` (and macOS `DYLD_INSERT_LIBRARIES`); config via env/`FAKETIME_TIMESTAMP_FILE` (`FAKETIME_CACHE_DURATION`, `FAKETIME_NO_CACHE`); uses shared memory between processes; GPL license | Per-process config; file re-read caching tradeoffs; README: "Without this argument [FAKETIME_DONT_FAKE_MONOTONIC] the java command usually hangs"; does not work for static binaries / Go; no multi-container orchestration, no verification, no scheduling help | Systems engineers, reproducible-builds, Jepsen-style testing | Live cross-container control API, seqlock page (no file parsing per call), probes/doctor, deadline-safety focus, triggers/barriers, compose integration. **Note: users can DIY a basic version with libfaketime + shared volume.** |
| **Stripe Test Clocks** — https://docs.stripe.com/billing/testing/test-clocks | Simulate time for Stripe Billing objects (subscriptions, invoices, customer balances) in sandboxes | Server-side clock attached to Stripe sandbox objects; each advance limited to "up to two subscription intervals at a time" | Your own services, DB and cron are untouched; doesn't affect live mode | Stripe Billing users | Same experience for *your* stack; complementary (advance both together — future integration idea) |
| **Node.js mock timers** — https://nodejs.org/api/test.html#class-mocktimers ; **@sinonjs/fake-timers** — https://github.com/sinonjs/fake-timers ; Jest/Vitest fake timers | Deterministic timers & Date in unit tests | In-process monkeypatching; `tick()` actually runs timers | Single process; doesn't affect DB/Redis/other services; risky in long-running servers | JS unit testers | Cross-process/cross-service time; integration level. SDK could reuse fake-timers ideas for opt-in timer execution. |
| **freezegun** — https://github.com/spulec/freezegun ; **time-machine** — https://github.com/adamchainz/time-machine | Freeze/travel time in Python tests | In-process patching (time-machine patches C-level functions) | Single process | Python testers | Same as above |
| **Testcontainers** — https://testcontainers.com/ | Throwaway real dependencies in tests | Library API controlling Docker | No time control (could host ChronoStack later) | Integration testers in many languages | Time dimension; possible future Testcontainers module |
| **Toxiproxy** (Shopify) — https://github.com/Shopify/toxiproxy | TCP-level network faults | Proxy with HTTP API; toxics: latency, bandwidth, slow_close, timeout, reset_peer, slicer, limit_data, packet_loss; "down" = disabling a proxy (`enabled: false`) | No time virtualization; faults applied in real time; seeding not evaluated | Resilience testers | Faults on the virtual timeline; v0.2 could drive Toxiproxy instead of reimplementing |
| **WireMock** — https://wiremock.org/docs/simulating-faults/ | HTTP stubbing, delays, faults | HTTP mock server | Mocks rather than proxies real services; real-time based | API testers | Virtual-time outage windows on real receivers |
| **Chaos Mesh TimeChaos** — https://chaos-mesh.org/docs/simulate-time-chaos-on-kubernetes/ | Clock skew in Kubernetes pods | Kubernetes CRD; configurable `clockIds` (default `CLOCK_REALTIME`, can include `CLOCK_MONOTONIC`); affects PID 1 of the container and its children. Injection mechanism is not described on the docs page (unverified) | Kubernetes-oriented; skew-oriented, not a lifecycle workflow | SRE/chaos engineers | Local compose, no privileges, lifecycle runner. Its source is worth studying for future Go support. |
| **Pumba** — https://github.com/alexei-led/pumba | Docker chaos (kill, netem delay/loss) | Docker API + `tc netem` | No time virtualization | Chaos testing on Docker | Time + lifecycle |

| **Antithesis** — https://antithesis.com/ | Deterministic simulation of whole systems | Deterministic hypervisor (commercial SaaS) | Commercial, heavyweight | Teams with serious distributed-systems risk | ChronoStack is the lightweight, local, free end; must not claim determinism |

## Positioning implications

* Don't claim "first" or "only". Claim: *the easiest way to make your whole compose stack agree on a fake date — and safely run the jobs that depend on it.*
* The defensible bundle is **(cross-service time) + (scheduler-aware stepping with barriers) + (reports/agent control)**. Each piece alone exists elsewhere.
* Potential partnerships/integrations: Testcontainers module (v1.0), Toxiproxy driver (v0.2), Stripe test clock sync (idea).
